# Nodes 01-03, 08-09: Unified Extraction of Object and Problem-Type Nodes (v5)

## [Output Requirements] (Must be strictly followed)

**Directly output a pure JSON array, starting from `[` and ending with `]`, without any other text in between.**

---

## [Task]

Extract 5 types of nodes involved in the paper in one pass: object domain, object type, operating conditions, PHM task, and problem scenario. Output a multi-node JSON array.

### The 5 Types of Nodes Involved

| No. | Node Type | Multiple Nodes | node_name Options |
|------|---------|-------|--------------|
| 01 | Object Domain | No (1) | Choose 1 from 8 |
| 02 | Object Type | Yes (1-N) | Fill null |
| 03 | Operating Conditions | No (1) | Choose 1 from 3 |
| 08 | PHM Task | No (1) | Choose 1 from 5 |
| 09 | Problem Scenario | Yes (1-N, maximum 3) | Choose 1 from 10 (multi-select allowed, maximum 3) |

## [Definitions of Each Node Type]

### Node 01: Object Domain

**Definition**: The industrial application domain in which the paper's research object is situated.

**node_name Choose 1 from 8**: `Aerospace` | `Space` | `Marine` | `Industrial` | `Nuclear` | `Electronics` | `Vehicle` | `Other`

**Discrimination**: `Aerospace` = aero-engine / aircraft; `Space` = satellite / spacecraft; `Marine` = ship / vessel; `Industrial` = manufacturing / wind turbine; `Nuclear` = nuclear / reactor; `Electronics` = motor / transformer; `Vehicle` = automotive / vehicle / railway; `Other` = medical / bridge / construction

**Fields**: `node_original_name` = original English text from the paper; `node_name` = choose 1 from 8; `node_description` = describe the domain in English, 1-3 sentences. **Extract only the domain involved in the paper's own experiments.**

---

### Node 02: Object Type

**Definition**: The specific mechanical or electrical equipment, etc., that the paper diagnoses / predicts / detects.

| Paper Expression | Corresponding Equipment |
|---------|---------|
| bearing / rolling bearing | Bearing |
| gearbox | Gearbox |
| motor / electric motor | Motor |
| engine / turbine | Engine |
| battery / lithium battery | Battery |

Multiple devices → multiple nodes (N1/N2...); `node_original_name` = original English text; `node_name` = null. **Extract only the equipment involved in the paper's own experiments.**

---

### Node 03: Operating Conditions

**Definition**: Key physical parameters (speed / load / temperature, etc.) under experimental or actual operating conditions.

**node_name Choose 1 from 3**: `Single Condition` | `Multiple Conditions` | `Variable Conditions`

**Decision Steps**:
1. **Is it variable conditions**: The paper explicitly mentions `time-varying` / `non-stationary` / `dynamic` and describes the paper's own experimental conditions → variable conditions; otherwise, proceed to the next step
2. **Multiple conditions vs. single condition**: Independent experiments under multiple different fixed parameters → multiple conditions; single fixed parameter → single condition

⚠️ `variable speed` ≠ variable conditions; strictly follow the two-step decision.

**Fields**: `node_original_name` = original English text; `node_name` = choose 1 from 3; `node_description` = two-paragraph format — paragraph 1: quantity and type; paragraph 2: parameters and values for each condition.

---

### Node 08: PHM Task

**Definition**: The core technical objective of the paper.

**node_name Choose 1 from 5**: `Detection Task` | `Diagnosis Task` | `Prediction Task` | `Assessment Task` | `Other Task`

**Discrimination**: Determine the output form of the technical objective — whether it is anomaly (→ detection); identify fault type (→ diagnosis); predict the future (→ prediction); evaluate current state (→ assessment).

| node_name | English Keywords |
|-----------|-----------|
| Detection Task | anomaly/fault/health detection, condition monitoring |
| Diagnosis Task | fault diagnosis/classification/identification |
| Prediction Task | RUL prediction, remaining useful life, prognosis |
| Assessment Task | health/performance/reliability assessment |

**Fields**: `node_original_name` = original English text; `node_name` = choose 1 from 5; `node_description` = describe the specific task in English.

---

### Node 09: Problem Scenario

**Definition**: The fundamental problems in the PHM domain that the paper targets.

**⚠️ Important: This type allows a single paper to contain multiple problem scenarios (N1, N2, N3... incrementing). As long as the paper explicitly identifies multiple problems, all of them must be extracted. Note: multiple problems may be included, but they must be the problems explicitly targeted by the authors in this paper; problems reviewed in the introduction that belong to other works are not in scope.**

**⚠️ The number of problem scenarios extracted per paper must not exceed 3 — encouraging the LLM to choose the most typical and core problems.**

**node_name Choose 1 from 10 (multi-select allowed, maximum 3)**: `Small Fault Samples` | `Zero Fault Samples` | `Distribution Discrepancy` | `Uncertainty` | `Compound Faults` | `Complex Systems` | `Early Degradation Prediction` | `Multi-Source Heterogeneous / Multimodal Data` | `Trustworthiness / Interpretability` | `Other`

| node_name | Challenge | Keywords |
|-----------|------|--------|
| Small Fault Samples | Sample insufficiency / missing | few-shot, data imbalance, scarce, etc. |
| Zero Fault Samples | A certain type of fault is completely unseen | zero-shot, unseen fault, etc. |
| Distribution Discrepancy | Cross-domain / cross-equipment | domain shift, cross-domain, transfer, etc. |
| Uncertainty | Noise / label / model uncertainty | uncertainty, noise robustness, etc. |
| Compound Faults | Compound fault diagnosis | compound / mixed fault, etc. |
| Complex Systems | Difficulties in fault analysis, modeling, and reasoning brought by complex object composition | system-level, complicated composition, etc. |
| Early Degradation Prediction | Identification of early weak faults, degradation modeling, and life prediction | incipient fault, degradation modeling, RUL prediction, etc. |
| Multi-Source Heterogeneous / Multimodal Data | Difficulties in unified modeling of multi-sensor, multi-modal, multi-source data | multimodal fusion, heterogeneous data, sensor fusion, etc. |
| Trustworthiness / Interpretability | Interpretable, physics-consistent, trustworthy PHM | interpretability, physics-informed, etc. |
| Other | Problems that cannot be classified into the above 9 categories | Depending on the specific situation |

**Multiple-Problem Decision Rules**:
- The paper explicitly proposes multiple different challenges / problems → extract multiple nodes (N1, N2...)
- For example: the paper simultaneously discusses the few-shot problem and the domain shift problem → 09_N1 = Small Fault Samples, 09_N2 = Distribution Discrepancy
- For example: the paper discusses few-shot + uncertainty → 09_N1 = Small Fault Samples, 09_N2 = Uncertainty
- **Must be chosen from the 10 options above**; no new options may be created
- **The number of problem scenarios extracted per paper must not exceed 3** — encouraging the LLM to choose the most typical and core problems

**Fields**: `node_original_name` = original English text; `node_name` = choose 1 from 10 (multi-select allowed, maximum 3); `node_description` = describe the specific problem in English. **Each node fills in one option independently; do not mix multiple problems in one node_description.**

## [Mandatory Constraints]

1. `node_name` must be filled in with **standard English options**; English original text or non-standard variants are prohibited
2. 01/03/08 each have **1 node** (no more, no less); 02/09 may have multiple (N1, N2, N3... incrementing)
3. **Extract only those involved in the paper's own experiments**, ignoring Introduction / Related Work / Baseline methods
4. When `node_description` is not null, fill in an English description
5. **For type 09, each node fills in only one option**; do not mix multiple problems within a single node
6. **For type 09, extract at most 3 nodes per paper**; for the excess, select the most typical problems
